Allura Works04

How it works

A tiny engine on top of deep construction knowledge.

rate  = baseRatePerM2 × finish × location
total = rate × areaM2
stageCost = total × elementWeight

Cost is computed top-down — credible immediately, no waiting for perfect data. Material quantities are stored as rates (blocks per m², cement per m²), so one template produces a correct, scaled material list for any floor area. As real prices mature, the numbers converge toward bottom-up accuracy without a rebuild.

One dataset, two views

A single array of stages drives both the build journey (timeline & storytelling) and the QS-style cost plan — they can never drift apart.

Allura Works05

Why this scales

The knowledge is the moat. Growth is content, not code.

The core object — BuildingTemplate

Every project on the platform is one JSON document: base rate, multipliers, element weights, and stages with materials stored as rates.

  • Adding the 2nd, 10th, or 100th house type = adding a document, never writing code
  • Published through an admin panel — no developer in the loop
  • Photos, plans, and refined prices drop into existing slots

What competitors would have to copy

  • Verified cost rates per m² across regions and finish levels
  • Stage-by-stage weights, durations, and material rates validated on real Kenyan builds
  • A growing library of real stage photos and professional-drawn plans

The software is a thin engine. The construction intelligence inside the templates is what a stranger pays for — and it compounds with every project added.

Allura Works06

The team — two roles, one contract

The developer builds the engine. The construction engineer builds the intelligence.

Reginald — Developer · "the engine"

  • Data model & schema — defines the BuildingTemplate / StageTemplate shape
  • generateEstimate() — the provably-correct pure calculation function, with tests
  • Admin panel & persistence — the CRUD that lets knowledge enter without code
  • Frontend — input flow, results page, donut, timeline; renders whatever a template contains
  • Payments & reports — the KES 500 unlock and PDF generation

Owns correctness: the math, the tests, the uptime. Never invents a construction fact.

Allan — Construction Engineer · "the intelligence"

  • Rates & multipliers — cost per m², finish and location factors, element weights
  • Stages — the real sequence, durations, descriptions, and tips per house type
  • Materials & prices — quantities as rates (per m² / per floor) and current market prices
  • Professionals per stage — who is needed, when, and what they check
  • Field content — stage photos from live sites, validation against real builds; delivers the billed expert opinions

Owns credibility: the numbers a stranger would pay for. Never touches code — fills a form.

The contract between them is the BuildingTemplate JSON. Fixed early, it lets both work in parallel: the engine is built and tested against a draft while the real numbers are refined — and refined numbers drop in without touching code.
